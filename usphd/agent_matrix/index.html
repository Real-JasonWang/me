The Unified Autonomous Agent Synthesis

Modern AI agents bridge high-level human objectives and low-level system execution through four interlocking pillars. Integrating strategic planning, long-running autonomous execution loops, delegated browser subagents, and precision DevTools MCP protocols enables resilient, end-to-end software automation.

Pillar IV Protocol

Pillar I Deep Dive

/plan Architecture & Artifact Protocol

The /plan workflow establishes strict alignment between user and agent before making code modifications. It prohibits unvetted mutations, structures exploratory codebase research, and enforces artifact-driven accountability.

Phase 1: Exploration

Examines files, directory structures, dependencies, and configuration. Provides verbal reasoning updates so the user can follow along.

Phase 2: Plan Authoring

Writes formal technical plan to artifact directory with RequestFeedback: true and UserFacing: true in ArtifactMetadata.

Phase 3: Approval Gate

Execution remains blocked until user approves the plan. No modifying tool calls or mutating terminal commands allowed beforehand.

Implementation Plan Artifact Specification Path: <Artifact Directory>/<plan_name>.md

## [Goal Description]
Problem statement, background context, project scope, and what the changes accomplish.
## User Review Required
Critical design decisions, breaking changes, schema migrations, and security implications using GitHub alerts (> [!IMPORTANT], > [!WARNING], > [!CAUTION]).
## Open Questions
Architectural trade-offs, underspecified edge cases, and design questions requiring user clarification.
## Proposed Changes
Files grouped logically by component or architectural layer, ordered dependencies-first.
#### [NEW] path/to/file.ext
#### [MODIFY] path/to/file.ext
#### [DELETE] path/to/file.ext
Includes explicit code snippets, unified diffs, and implementation notes.
## Verification Plan
### Automated Tests: Exact shell commands to run unit tests, integration tests, and linters.
### Manual Verification: Step-by-step instructions for human verification of behaviors and edge cases.

Walkthrough Artifact Specification Path: <Artifact Directory>/walkthrough.md

Authored after completing work. For related follow-ups, updates the existing walkthrough instead of creating duplicate files.

• Changes Made: Summary of implemented functionality and files touched.
• What Was Tested: Automated test suites run, compiler checks, and diagnostic scripts executed.
• Validation Results: Terminal exit codes, test outputs, metric improvements, and audit logs.
• Visual Proof: Embedded screenshots, recordings, and trace URLs demonstrating functional correctness.

Pillar II Deep Dive

/goal Long-Running Autonomous Execution

The /goal slash command configures the agent for extended, unattended execution (such as overnight tasks or large-scale migrations). It demands exhaustive thoroughness and mandates continuous self-auditing until objectives are fully verified.

Thoroughness Mandate

Standard interactive agents often halt after applying initial edits, leaving verification to the user. Under /goal, stopping prematurely is strictly prohibited. The agent must proactively verify compiler outputs, run full test suites, reproduce edge cases, and self-correct regressions.

Rule: Never stop when a test fails. Triage error logs, patch code, and re-run verification until all gates pass.

Autonomous Termination Protocols

The platform monitors agent execution. To officially conclude or cancel a goal, the agent must output specific signalling tokens in its final turn:

Goal Complete Token: <!-- GOAL_COMPLETE -->
Goal Cancelled Token: <!-- GOAL_CANCELLED -->

State Persistence & Liveness Scheduling

Persistent Scratchpad

Stored at <appDataDir>/brain/<conversation-id>/scratch/. Persists one-off scripts, intermediate payloads, and verification outputs across turns without polluting project repositories.

Reactive Wakeup

The agent never loops or polls synchronously. Once a background task or subagent is launched, the agent concludes its turn. The system reactively wakes the agent when messages or task completions occur.

Schedule Tool Integration

Uses schedule tool with one-shot timers or recurring cron jobs for periodic health checks, heartbeats, and timeout safeguards.

Pillar III Deep Dive

/browser Subagent Architecture

The /browser directive delegates web browsing, DOM inspection, and web application interactions to a specialized autonomous subagent, ensuring conversation context remains clean and focused.

Subagent Dispatch Mechanics

Invoked via the invoke_subagent API. The subagent operates with its own distinct conversation context, system instructions, and specialized browser tool bindings. 

invoke_subagent({
  Subagents: [{
    TypeName: "browser",
    Role: "Browser Automation Specialist",
    Prompt: "Navigate to localhost:3000, inspect accessibility tree, and report errors.",
    Workspace: "inherit",
    Model: "inherit"
  }]
})

Runtime & Profile Persistence

The browser subagent utilizes Chrome DevTools Protocol and Puppeteer backed by a persistent Chrome profile located at:

~/.gemini/antigravity-browser-profile

Maintains cookies, session storage, and authenticated states across sessions, enabling testing of logged-in flows without repeated authentication steps.

Security Policies & Access Controls

Domain Allowlisting

Governed by browserAllowlist.txt. Restricts browser navigation strictly to approved target hostnames and staging environments.

Network Access Policy

Configurable via agent settings (allow, ask, deny). Prevents unintended external requests during local development.

OS Process Isolation

Runs browser instances within platform sandboxes (macOS Seatbelt, Linux namespace cgroups, Windows job containers).
